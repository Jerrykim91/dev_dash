## 0. 요약

1. **v1은 청사진 한 장의 인상만 보고 템플릿을 정했습니다.** 그래서 네 가지 기준이 빠져 있었습니다.
   - 각도: 생성물이 2:1이 아니라 좌우 비대칭으로 10~15° 돌아가 있었습니다.
   - 축척: 실제 크기 기준 없이 bbox 비율로 크기를 정했습니다.
   - 좌석: 캐릭터가 의자 옆에 서서 포즈만 바꿨습니다.
   - 액션: 서비스 액션 12종 가운데 4종만 그림이 있었습니다.
2. **표준의 기준점은 그림이 아니라 기하와 데이터입니다.** 기준은 다섯 가지입니다.
   - 미터법 축척
   - 좌석·상호작용 포인트 스키마
   - 깊이 규칙
   - 회전·미러 스키마
   - 액션 3계층 모델
   그림은 이 기준 위에서 칠하는 것입니다.
3. **제작 방식을 기하 우선(블록아웃 가이드)으로 바꾸면 각도와 위치가 수치로 고정됩니다.** 실증 결과는 다음과 같습니다.
   - 책상 각도: 31.5°/22.3° → 27.2°/26.5° (목표 26.6°)
   - 블록아웃과 실루엣 일치도: 0.92
   - 걷기 4프레임의 발 위치 오차: ±1px
4. **유사 서비스에서는 구조를 차용합니다.**
   - 영역 스키마: WorkAdventure
   - 회전 스키마와 좌석 방향 규칙: Pixel Agents
   - 앉기 보정: SkyOffice
   - 액션 우선순위와 파트 세트, 좌석 규칙(몸 방향 = 의자 회전): Habbo/Nitro (§6)
   - 레이어 순서: LPC
   - 근접 대화 버블: WorkAdventure

## 2. 기준점 ① 공간 기하

### 2.1 투영과 방향
- 2:1 다이메트릭(26.565°)을 씁니다. 화면 기준 +x는 우하, +y는 좌하입니다(기존 `CoordinateSystem`).
- 바라보는 방향(facing)은 대각 4방향입니다. 이동이 4방향 격자라서 8방향은 필요 없습니다.

| facing | 화면 방향 | 그리는 뷰 | 반전 관계 |
|---|---|---|---|
| south (+y) | 좌하 | **앞 3/4** (그림) | east와 좌우 반전 |
| east (+x) | 우하 | south 반전 | — |
| north (−y) | 우상 | **뒤 3/4** (그림) | west와 좌우 반전 |
| west (−x) | 좌상 | north 반전 | — |

Habbo의 8방향 중 3방향을 반전으로 만드는 규칙, Pixel Agents의 `3-way-mirror`와 같은 원리입니다.

### 2.2 월드 축척 — 1타일 = 1m, 높이 1m = 32px

평면은 타일 64×32(1m×1m), 높이는 1m당 32px입니다(Habbo 계열의 높이 1단 = 32px와 같음). 모든 블록아웃은 아래 치수표를 따릅니다.

| 대상 | 실치수 | 높이(px) | 비고 |
|---|---:|---:|---|
| 책상 상판 | 0.76m | 24 | 2×1, 사용 면은 +y |
| 모니터 상단 | 1.30m | 42 | 좌석 타일 중심 x에 정렬 |
| 사무 의자 좌판 / 등받이 | 0.375m / 0.92m | 12 / 29 | **표준 좌석 높이 12px** (§10에서 15px → 12px로 수정) |
| 소파 좌판 / 등받이 | 0.345m / 0.80m | 11 / 26 | 좌석 보정 −1px |
| 카페 테이블 / 낮은 테이블 | 0.75m / 0.45m | 24 / 14 | |
| 책장 | 1.80m | 58 | |
| 문 | 2.10m | 67 | |
| 벽 | 2.50m | 80 | 프레임 128×160 안에서 최대 88px |
| 캐릭터(서 있음) | — | **54** | 구 머리 반지름 0.27m(지름 약 21px, 39%), 몸통 0.58m, 다리 0.44m, 머리카락 +4px까지 허용 |
| 캐릭터(앉음) 머리 꼭대기 | — | 약 52 | 서 있을 때와 거의 같음(치비는 다리가 짧음) |

- **캐릭터 표시 배율을 1.125에서 1.0으로 바꿔야 합니다.** 가구를 미터 축척으로 그리면 캐릭터만 12.5% 커질 이유가 없습니다(§8 결정 5).
- 걷기 스트립 실험에서 마네킹 머리를 크게(0.78m) 잡았더니 전신이 62px로 나왔습니다. AI는 블록아웃 비례를 그대로 따르므로, **비례는 마네킹 파라미터로 통제합니다.**

### 2.3 앵커와 footprint
v1과 같습니다. 앵커는 원점 타일 (o.x, o.y)의 중심이고, 프레임 128×160에서 (64,104)입니다. footprint 마름모 공식도 그대로 씁니다. **가이드 생성물은 캔버스 위치가 유지되므로, 블록아웃 앵커를 그대로 옮겨 배치하고 bbox 추정은 쓰지 않습니다.**

### 2.4 깊이 규칙 v2

`depth = (x + y) × 100 + offset`이고, x·y는 정렬 기준 타일입니다.

| 대상 | offset | 비고 |
|---|---:|---|
| 러그·바닥 장식 | 고정 레이어 | 기존 `visualLayers.rug` |
| 가구 lower | −15 | 정렬 타일 = footprint 중심 |
| 서 있는 캐릭터 | 0 (+ 타일 사이 이동 보간) | |
| 앉은 캐릭터 | 좌석 타일 +10 | 현재는 +1 |
| 가구 upper (등받이 등) | +20 | 현재는 +0.15 → **앉은 캐릭터보다 앞** |
| 매달린 조명 등 | +50 | |

- 근거: Pixel Agents는 뒤를 향한 의자를 캐릭터 앞에 그리고(`zY = (row+footprintH)*16+1`), SkyOffice는 `sittingShiftData`의 depthShift로 처리합니다.
- 실증: `preview/workstation.png`의 오른쪽 그림입니다.
- **3칸 이상 긴 가구**는 footprint 중심 정렬이 깨지는 경우가 있습니다. 2칸 이하로 제한하거나, 타일 단위 세로 슬라이스로 나눠 그립니다.

### 2.5 좌석·상호작용 포인트 스키마

참고한 구조는 다음과 같습니다.
- SkyOffice: 의자 `direction` + `sittingShiftData [x, y, depth]`
- Pixel Agents: `Seat{seatCol, seatRow, facingDir}`, 방향 우선순위(의자 방향 > 인접 책상 > 기본값)
- Habbo: logic의 canSit과 좌석 높이

```jsonc
// 가구 카탈로그 항목 (회전 0 기준. 회전하면 tile·facing도 함께 회전)
{
  "kind": "chair_office", "footprint": [1, 1],
  "rotationScheme": "4-way-mirror",          // §2.6
  "views": ["front", "back"],                 // 실제로 그리는 뷰
  "layers": { "lower": ["base", "post", "seat"], "upper": ["back"] },  // 블록아웃 파트 → 레이어
  "seats": [{ "tile": [0, 0], "facing": "north", "sitHeight": 15, "offset": [0, 0],
              "postures": ["sit"], "activities": ["idle", "type", "talk", "drink"] }],
  "placement": { "floor": true, "wall": false, "surface": false }
}
// 책상: 좌석은 없고 작업면(workSurface)을 선언
{
  "kind": "desk_work", "footprint": [2, 1], "rotationScheme": "4-way-mirror",
  "workSurface": { "edge": "+y", "slots": [{ "x": 0.5, "seatTile": [0, 1] }] },  // 모니터·키보드는 slot에 정렬
  "interactionPoints": []
}
// 서서 쓰는 오브젝트
{ "kind": "coffee_station", "interactionPoints": [{ "tile": [0, 1], "facing": "north", "activity": "drink", "posture": "stand" }] }
```

- **워크스테이션**은 기존 `workstations{desk_id, chair_id, approach}`를 일반화합니다. 책상 `workSurface.slot`과 의자 `seat`가 같은 타일·방향을 가리키도록 맵 검증기로 강제합니다. 이렇게 해야 "모니터는 좌석 정면에, 키보드는 손 위치에" 오는 조화가 데이터로 보장됩니다.
- **서버**가 해야 할 일:
  - 좌석 점유 잠금(1좌석 1명)
  - 앉으면 좌석 타일로 위치 스냅 (막힌 타일이지만 점유자에게만 허용)
  - facing 설정
  - 이동하면 해제하고 approach 타일로 복귀
  - 지금은 1.15칸 근접 검사만 하고 있음
- **클라이언트**는 좌석 seat의 `sitHeight`와 `offset`만 적용하고, 앉은 포즈 프레임은 표준 좌석 높이 12px에 맞춰 그립니다. Pixel Agents의 `CHARACTER_SITTING_OFFSET_PX`처럼 상수 하나로 처리합니다.

### 2.6 회전·미러 스키마 (Pixel Agents `rotationScheme` / `mirrorSide`)

| scheme | 그리는 뷰 | 4방향을 만드는 방법 | 예 |
|---|---|---|---|
| `1-way` | 1 | 회전 무관(대칭) | 원형 러그, 화분, 스탠드 조명 |
| `2-way-mirror` | 1 (front) | south ↔ east 반전. north·west = 같은 그림 | 뒷면이 보이지 않는 벽붙이 가구 |
| `4-way-mirror` | 2 (front, back) | front → south/east, back → north/west | 의자, 소파, 책상, 아케이드, 모니터 |
| `4-way` | 4 | 반전 없음 | 글자·비대칭 디테일이 있는 가구 |

- 회전 0/90/180/270은 facing south/east/north/west와 1:1로 대응합니다. Habbo 가구 방향 번호와의 대응은 §6에서 보강합니다.
- 프레임 키는 기존 `furniture/<kind>/<W>x<H>/<rot>/lower|upper`를 유지합니다. 반전은 아틀라스에 실제 반전 프레임을 넣습니다(렌더러 수정 없음).
- **반전 전제 조건:** 측면 두 면의 명암이 대칭이어야 합니다. 그렇지 않으면 4-way로 그려야 합니다(§8 결정 1).

### 2.7 영역 스키마 (WorkAdventure `AreaData` 차용)

```jsonc
"areas": [
  { "id": "focus-desks", "name": "집중 좌석", "tiles": [[4, 4], [4, 5]],
    "properties": [
      { "type": "silent" },                               // 말풍선·근접 대화 끔 (WA silent)
      { "type": "statusOnEnter", "status": "focusing", "mode": "suggest" },
      { "type": "seatGroup", "workstations": ["workstation-01"] } ] },
  { "id": "meeting-a", "name": "회의실 A", "properties": [
      { "type": "meeting", "roomName": "meeting-a", "trigger": "onenter" },  // WA jitsiRoomProperty 구조
      { "type": "maxUsers", "maxUsers": 15 }, { "type": "restrictedRights", "readTags": ["attendee"] } ] },
  { "id": "cafe-t1", "name": "카페 테이블 1", "properties": [{ "type": "chatScope", "scope": "area" }] },  // Gather/ZEP 프라이빗 영역: 같은 id면 대화 공유
  { "id": "spawn", "properties": [{ "type": "start", "isDefault": true }] }
]
```

- 이벤트는 `onEnter`/`onLeave(areaId, {reason: "initial"|"move"})`입니다.
- 근접 대화 버블 기본값은 WA 수치(판정 64px, 반경 48px, 최대 4인)를 아이소메트릭 거리로 환산해 씁니다.
- 지금 흩어져 있는 `chat_bubbles_allowed`, `workstations`, 회의 ACL을 이 스키마 하나로 모읍니다.

## 3. 기준점 ② 캐릭터 액션·애니메이션

### 3.1 서비스 액션 인벤토리 (현재 코드 기준)

| 출처 | 값 | 현재 그림 | 표준 v2 표현 |
|---|---|---|---|
| `AvatarAction` | idle | idle | stand.idle |
| | walking | walking | stand.walk |
| | sitting (의자) | sitting (의자 옆에서) | **sit.idle + 좌석 스냅** |
| | working / typing (책상) | typing (아무 칸에서) | **sit.type (워크스테이션 좌석)** |
| | resting (소파·침대) | sitting | sit.relax / lay.rest |
| | drinking (커피) | **idle** | stand.drink 또는 sit.drink + 컵(carry) |
| | chatting | **idle** | 지금 자세 + talk 활동 + "…" 오버레이 |
| | meeting | **idle** | sit.talk (회의 좌석) |
| | away | **idle** | 지금 자세 + Zz 오버레이, 어둡게 |
| | vacation / after_work | **idle** | 관람(반투명) 또는 숨김 — 정책 필요 |
| `WorkStatus` | before_work · working · meeting · focusing · break · outside · after_work · vacation | 상태 메시지 텍스트 | 상태 아이콘 말풍선(오버레이) + 위치에 따른 기본 활동(§3.3) |
| 오브젝트 | bookshelf / whiteboard (menu) | 없음 | stand.read / stand.present |
| | computer (dashboard), arcade (미니게임) | 없음 | sit.type / stand.play |
| | 포털 출입, 회의 로비 | 없음 | 문 앞 facing + 페이드 |
| 기타 | 채팅 말풍선, 귓속말, 가챠·코인 보상, 출석 | UI | 오버레이 이펙트(반짝임, 코인) |
| 청사진 | `E` 이모티콘 | 미구현 | 제스처 one-shot(§3.2 L3) |

### 3.2 3계층 + 오버레이 모델 (Habbo posture/gesture/effect, LPC zPos 차용)

| 계층 | 성격 | 값 | 규칙 |
|---|---|---|---|
| **L1 자세** | 배타, 위치가 결정 | stand · walk · sit · lay | 좌석에 앉으면 sit, 침대면 lay. 이동하면 walk가 되고 좌석 해제 |
| **L2 활동** | 자세별 허용 목록 | idle · type · talk · drink · read · play · present · relax · sleep | 좌석·상호작용 포인트의 `activities`가 허용 범위. 상태 매핑(§3.3)이 기본값을 정함 |
| **L3 제스처** | 1~2초 one-shot, 상반신 | wave · nod · clap · cheer · thumbsup | L2를 잠시 덮고 복귀. stand와 sit에서만 가능 |
| **L4 오버레이** | 캐릭터 프레임과 별개 | 상태 아이콘, Zz, 헤드폰(focusing), 김, 컵, "…", 반짝임 | 캐릭터 머리·손 앵커(프레임 메타데이터)에 붙임 |

- **우선순위**는 walk > 제스처 > 활동 > 자세 idle입니다.
- **네트워크 계약**은 지금의 `action` 하나를 `{posture, activity, gesture?, carry?, seatId?}`로 나눕니다. 기존 `AvatarAction` 값은 이 조합으로 변환합니다.

| WorkStatus | 워크스테이션 좌석 | 회의 좌석 | 소파·카페 | 서 있음 | 오버레이 |
|---|---|---|---|---|---|
| working | sit.type | sit.talk | sit.idle | stand.idle | 💻 |
| focusing | sit.type | — | — | stand.idle | 🎧 + 헤드폰, 영역 silent |
| meeting | sit.idle | sit.talk | sit.talk | stand.idle | 👥 |
| break | sit.relax | — | sit.drink / relax | stand.drink | ☕ |
| outside / vacation / after_work | 정책 결정 필요: 숨김, 반투명 관람, 자리에 부재 표시 | | | | 🌙 |
| before_work | — | — | — | stand.idle | ⏰ |

### 3.4 클립 사양 (1 프리셋 기준)

프레임은 48×64, 발 기준점은 (24,58)입니다. 앉은 프레임은 표준 좌석 높이 12px에 앉은 모습으로 그립니다. 방향은 south·north 2개를 그리고 east·west는 반전으로 만듭니다.

| 클립 | 프레임 | fps | 반복 | 비고 |
|---|---:|---:|---|---|
| stand.idle | 2 | 1.2 | loop | 숨쉬기 |
| stand.walk | 4 | 8 | loop | 실증 완료(`walk_s_*`) |
| sit.idle | 2 | 1.5 | loop | |
| sit.type | 2 | 5 | loop | 실증 완료(`sit_g`, north) |
| sit.talk | 2 | 4 | loop | 회의, 카페 |
| sit.relax | 1 | — | hold | 소파에 기댄 자세 |
| sit.drink / stand.drink | 3 | 3 | once → hold | 컵 오버레이 |
| stand.read / stand.present / stand.play | 2 | 2 / 2 / 6 | loop | 책장, 화이트보드, 아케이드 |

- 생성 단위는 "클립 × 방향" 스트립 1장이라 약 32장, 1장에 약 50초 걸립니다.

### 3.5 캐릭터 구성 방식
- **A. 프리셋 전신 + 팔레트 램프 교체 (MVP 추천):** 머리·피부·상의·하의 4개 램프만 색을 바꿉니다. AI 생성과 잘 맞고, 커스터마이징은 색 단위로 제한됩니다.
- **B. 파츠 레이어:** WA의 `body → eyes → hair → clothes → hat → accessory` 순서와 LPC zPos(body 10, legs 20, heads 100, hair 120, hat 139 등)를 씁니다. 커스터마이징 자유도는 높지만, AI로는 파츠별 정렬을 맞추기 어려워 수작업 비중이 큽니다.
- 처음부터 B로 갈 수 있도록 프레임 키에 `layer` 슬롯을 비워 두는 것을 권장합니다.

## 6. Habbo/Nitro에서 차용할 세부

출처는 nitro-renderer(GPL-3.0), shroom(LGPL-3.0), Arcturus 에뮬레이터 소스입니다.

### 6.1 액션 정의 스키마 → §3.2를 데이터로 표현
Habbo의 액션 정의 필드 `state / precedence / main / activepartset / prevents / preventheadturn`를 그대로 JSON으로 씁니다.

```jsonc
// shared/avatar-actions.json (제안). precedence는 숫자가 작을수록 우선(나중에 적용되어 겹치는 파트를 덮음)
[
  { "state": "lay",  "main": true, "precedence": 100, "prevents": ["talk", "gesture.*", "drink"], "canvas": "lay" },
  { "state": "sit",  "main": true, "precedence": 103, "prevents": [] },
  { "state": "drink", "precedence": 200, "partset": "handRight", "carry": "cup" },
  { "state": "gesture.wave", "precedence": 205, "partset": "handLeft", "timeoutMs": 2000 },
  { "state": "type", "precedence": 300, "partset": "hands" },
  { "state": "talk", "precedence": 500, "partset": "speak" },
  { "state": "sleep", "precedence": 520, "overlay": "zz", "preventHeadTurn": true },
  { "state": "walk", "main": true, "precedence": 600 },
  { "state": "stand", "main": true, "precedence": 1000, "default": true }
]
```

- 합성 규칙(Nitro `filterActions`):
  1. 켜진 액션들의 `prevents`에 걸린 액션을 지웁니다.
  2. 남은 액션을 precedence 내림차순으로 적용합니다.
  3. 결과적으로 겹치는 파트는 숫자가 작은 액션이 이깁니다.
- `main` 자세는 하나만 켜집니다. Habbo에서 mv·std·sit·lay가 서로 배타인 것과 같습니다.
- **파트 세트 덮어쓰기는 파츠 레이어 구조(§3.5 B)일 때만 작동합니다.** A안(전신 프리셋)에서는 자세×제스처 조합마다 클립을 따로 그려야 합니다(예: stand.wave와 sit.wave).

### 6.2 방향·반전
- Habbo는 8방향 중 0,1,2,3,7을 그리고 4,5,6은 반전합니다. 반전할 때 좌우 손 파트(rh↔lh)를 서로 바꿉니다.
- 우리는 이동이 4방향 격자라 대각 4방향만 씁니다(§2.1). south·north 2개를 그리고 반전합니다.
- **손에 든 물건(컵 등)이 반전으로 반대 손에 가는 문제**는 Habbo처럼 손 아이템을 오버레이로 빼서 해결합니다. 오버레이 앵커를 "주로 쓰는 손" 기준으로 반전 시 다시 계산합니다.
- 머리와 몸 방향 분리(머리는 몸 기준 ±1)는 8방향 전제라 1차에서는 쓰지 않습니다.

### 6.3 좌석·눕기 규칙 (Arcturus `Room.java`)
- 앉으면 위치 = 의자 타일, **몸 방향 = 의자 회전**, 높이 = 의자 `stack_height`입니다. 우리 `seats[].facing`과 `sitHeight`가 이 구조입니다.
- Nitro는 앉은 방향을 사분면 중앙으로 스냅합니다. 우리 4방향 facing과 같은 결과입니다.
- 침대는 방향 = `rotation % 4`이고 위치를 침대 축에 정렬합니다. 눕기 캔버스는 128×80(가로)이고, 우리 `lay` 프레임 96×64와 대응합니다.

### 6.4 가구 시각화 포맷
- visualization의 `layers{z, alpha, ink, ignoreMouse, tag}`를 차용합니다.
  - z는 우리 lower(−15)/upper(+20) offset에 대응합니다.
  - `ink: ADD`는 램프 불빛·모니터 발광 레이어에 씁니다.
  - `ignoreMouse`는 그림자나 빛처럼 클릭되면 안 되는 레이어에 씁니다.
- `directions`는 방향별 레이어 덮어쓰기입니다. 없는 방향을 요청하면 가장 가까운 아래 값으로 대체하는데, 우리 `rotationScheme`의 대체 규칙과 같습니다.
- `animations[state]`는 가구 상태별 애니메이션입니다(모니터 켜짐·꺼짐, 커피머신 작동). Pixel Agents의 state·animation 중첩 그룹과 같은 개념입니다.
- 에셋 이름은 Habbo `{type}_{size}_{layer}_{dir}_{frame}`과 같은 정보를 담되, 기존 키 `furniture/<kind>/<W>x<H>/<rot>/<layer>`를 유지합니다(렌더러 호환).

### 6.5 방 기하 대조
| 항목 | Habbo | NOBIS v2 |
|---|---|---|
| 높이 1단 | 32px | 1m = 32px (같음) |
| 벽 높이 | 약 116px (3.6단) | 80px (2.5m). 높이려면 프레임 192 이상 필요 |
| 바닥 두께 | 8px | 기존 바닥 가장자리 렌더 유지 |
| 깊이 정렬 | `(x+y)·1000 + z`, 아바타 +1 | `(x+y)·100 + offset` (§2.4) |

### 10.3 검증 중 발견해서 표준에 반영한 것
1. **좌석 높이 15px → 12px.** 치비 다리(0.44m)보다 좌석이 높으면 앉은 키가 선 키보다 커집니다. 앉은 엉덩이 높이를 선 엉덩이 높이에 맞췄습니다.
2. **마네킹 머리는 구(球)로.** 정육면체 머리를 주면 AI가 상자 머리(마인크래프트풍)로 그립니다. 수치(머리 40%)만으로는 치비가 되지 않고, 다리/몸통 비율(약 0.75)도 기준에 넣어야 합니다.
3. **정합 단계 필수.** 반대 뷰 생성(레퍼런스 3장)에서 AI가 각도는 지키지만 위치·크기가 어긋납니다(IoU 0.59~0.73). 이동+확대 정합 후 0.87~0.96이 됩니다. 클립은 스트립 전체를 한 번에 정합해 프레임 간 움직임을 보존합니다.
4. **측면 명암 평준화는 후처리로.** "대칭 광원"을 프롬프트로 요구해도 AI는 +x 면을 4~20% 어둡게 칠합니다. 블록아웃 면 마스크로 파트별 밝기 중앙값을 맞춥니다. 이 단계가 있어야 반전 허용(결정 1)이 성립합니다.
5. **색 교체는 공통 인덱스 팔레트로.** 색상 범위로 픽셀을 고르면 외곽선과 주름이 섞입니다. 프리셋 전 프레임에 공통 팔레트(28색)를 씌우고, 의상 항목만 밝기 순서대로 램프에 매핑합니다. 프리셋마다 의상 색상 범위는 실측해서 등록합니다(`build.py TOP_HUE`).
6. **클립 간 머리 크기 편차.** 걷기 클립의 머리가 idle보다 커지는 경우가 있어, 키 게이트로 걸러 1회 재생성했습니다. 프롬프트에 "머리는 마네킹 구 크기에 정확히" 문구를 고정했습니다.

### 11.4 대량 생성 전에 고칠 것
1. **상태 말풍선 위치:** 앉으면 머리가 내려가는데 말풍선은 그대로라 모니터 위를 가립니다. head 앵커 기준으로 계산해야 합니다(C10).

4. **그림 혼재:** 로비 벽·바닥·테이블·램프와 1×1 책상은 아직 기존 그림입니다. 대량 생성 범위에 포함합니다.

## 12. 화면 배율 정책 — HiDPI·4K (2026-11-18)

### 12.1 문제였던 것
- 캔버스를 CSS 픽셀로만 그리고 있었습니다. 레티나·4K(DPR 2)에서는 브라우저가 1배 그림을 2배로 늘려 보여 주므로, 글자와 이름표가 뭉개졌습니다.
- 카메라 배율이 정수가 아니었습니다(로비 0.85, 휠 연속 줌). 그래서 그림 1픽셀이 화면에서 1픽셀이었다 2픽셀이었다 하며, 바닥 무늬가 불규칙(모아레)하고 대각선에 계단이 생겼습니다.

### 12.2 정책 (`frontend/src/game/systems/DisplayScale.ts`)
| 항목 | 규칙 |
|---|---|
| 캔버스 | 그리기 버퍼 = CSS 크기 × DPR(최대 3), 화면 표시 = CSS 크기(`Scale.NONE` + `zoom: 1/DPR`). 클릭 좌표는 Phaser가 환산 |
| 카메라 배율 | 장치 픽셀 / 월드 픽셀. 확대는 정수(1, 2, 3, …, 최대 ⌈1.8 × DPR⌉), 전체 보기는 1/2·1/3·1/4 |

### 13.5 벽·벽에 붙는 문 연결
- **벽 위치 규칙 (`frontend/src/game/visual/WallVisual.ts`):** 걸을 수 있는 칸마다 −x 이웃이 바닥이 아니면 좌상 벽(`x`), −y 이웃이 바닥이 아니면 우상 벽(`y`)을 그립니다. 앞쪽 두 면은 벽 없이 기존 렌더러의 바닥 턱만 남깁니다(시야 확보, Habbo 방식). 벽 깊이는 칸 깊이 −2로 모든 가구·캐릭터 뒤입니다.
- **방별 벽 테마:** 카페 `cafe`(벽돌), 회의실 `meeting`(패널), 정원·테라스 `railing`(난간), 나머지 `plain`.

- **로비 입구 이동(A안):** 뒤쪽 벽 y=1에 카페(4,1)·집중 업무존(11,1)·라운지(18,1)·정원(25,1), 뒤쪽 벽 x=1에 테라스(1,5)·회의실(1,14). 각 방에서 돌아오는 자리(`lobby_return`)는 문 바로 앞 칸입니다. 앞쪽 가장자리에 떠 보이던 동쪽 기둥은 뒤쪽 벽 끝(28,1)으로 옮겼습니다.
- **텍스처 메모리:** 가구·벽·문 프레임은 투명 여백을 잘라(trim) 담습니다(`pack_v2.py` `trim`). 캐릭터는 실행 중 좌우 반전 때문에 원래 크기 그대로입니다. 아틀라스 2048×1472(11.5MB) → 2048×661(5.2MB).
- **남은 것:** 비정형 방의 안쪽 꺾인 모서리에도 규칙대로 벽이 서서 일부 방(카페 오른쪽 등)이 복잡해 보입니다. 맵 배치 작업 때 방 외곽을 단순화하거나 안쪽 모서리 벽을 낮은 난간으로 바꾸는 방식을 정합니다.

## 14. 그림 밀도 2배(HD) — 흐림 개선 (2026-11-23)

### 14.1 원인과 시도
- **원인:** 렌더링은 정상(장치 픽셀 캔버스, 정수 배율, 최근접 필터). 흐림은 그림 자체에서 왔다. AI 원본(약 1250px)을 8분의 1로 평균 축소하면서 경계마다 중간색이 생기고, 48×64 캐릭터를 화면 3배로 키워 보면서 부드러운 톤이 뭉개져 보였다.
- **기각한 방법:** 색 줄이기·잡티 제거 후처리(눈·자판 등 디테일 손실), 격자 고정 재생성 v3(시험 후 삭제, 선명하지만 AI가 블록을 크게 잡아 그림이 단순해지고 캐릭터 방향이 틀어짐), 경계 중간색 제거 + 외곽선 보강(차이가 작음).
- **채택:** 같은 원본·같은 정합을 4분의 1로만 축소해 그림 밀도를 2배로 올리고, 게임에서 0.5배로 그린다. 디자인은 v2 그대로, 디테일은 2배.

### 14.2 규칙
| 항목 | 1배(기존) | 2배(HD) |
|---|---|---|
| 캐릭터 프레임 | 48×64, 발 (24,58) | 96×128, 발 (48,116) — 원점 비율 동일 |
| 가구·벽·문 프레임 | 128×160, 앵커 (64,104) | 256×320, 앵커 (128,208) |
| 바닥 타일 | 64×32 | 128×64 |
| 아틀라스 `scale` | 1 | 0.5 (그림 1px의 월드 크기) |
- 월드 좌표·좌석 높이·깊이 기준은 월드 단위라 그대로다. 그리는 쪽만 `frameScale(frame)`(아틀라스 `scale`)을 곱한다: 가구 lower/upper, 벽, 캐릭터(`avatar.scale` 0.5), 바닥은 표시 크기 지정이라 자동.
- **빌드:** `NOBIS_DENSITY=2 python3 build.py`(1배 빌드의 `qa.json` 정합값을 재사용, 전체 약 1분) → `norm_d2/`. QA 정본은 1배 빌드. `python3 pack_v2.py`(기본 밀도 2)는 2048×2048 한도로 여러 장을 만든다(`nobis-avatar-0`, `nobis-aigen-1`, …).
- **배율:** 카메라 배율 z에서 그림 1px = 장치 z/2 px. 기본 배율이 홀수(≥3)면 하나 위 짝수로 올린다(3 → 4). z < 2에서는 HD 아틀라스를 선형 필터로 바꿔 축소 시 2×2 평균(= 1배 그림)이 되게 하고, 그 이상은 최근접.
- **텍스처 예산:** 24MB → 48MB(새 그림 20.2MB + 예전 가구 11.9MB + 로비 1.6MB).
- **로비 바닥:** 로비 전용 1배 타일 대신 HD 타일셋(돌 = 업무 바닥, 나무 = 집 바닥). 없으면 로비 타일로 대체.
- **미리보기·초상화(SVG):** 잘린(trim) 프레임은 내용 상자만 잘라 보여 주고(`VisualFrame.trim`), 밀도만큼 줄여 기존 월드 단위 viewBox에 맞춘다(`FrameImage`). 여백 자르기 이후 미리보기가 어긋나던 문제도 함께 해결.
- **남은 것:** 로비 전용 그림(개인 집 입구 액자, 기둥, 안내 데스크 등)과 예전 가구 아틀라스는 아직 1배. 같은 방식으로 원본이 있으면 HD로, 없으면 재생성 대상.

## 15. 파트 분리 시험(페이퍼돌) — sow 시트 방식 (2026-11-23)

### 15.1 구조 (`infra/visual/aigen/parts/`)
- **잠긴 템플릿(`template.py`)**: 방향별 몸 시트 1장(1536×1024, 5×2칸, 마네킹 6배: 대기 2·걷기 4·앉기 2·타이핑 2). 프레임 원점은 3의 배수라 원본 3px = HD 1px. 머리 시트 1장(4×2칸, 머리 구 12배: 스타일 4종 × 앞·뒤). 칸·발·머리 중심·파트 마스크를 JSON·마스크로 함께 저장.
- **생성 11회**: 기본 몸(민머리·회색 기본 옷) 앞·뒤 2장 → 정합한 기본 몸 시트를 편집 대상으로 상의 2종·하의 2종 × 앞·뒤 8장("옷만 칠하고 나머지는 그대로") → 머리 시트 1장.
- **처리(`process.py`)**: 시트 전체 배율·이동 정합 후 칸마다 이동 재정합(칸별 IoU 0.87~0.97). 옷 레이어 = 내 영역(가장 가까운 마네킹 파트가 몸통·팔 / 다리)에서 기본 몸과 달라진 픽셀(5×5 중앙값 흐림 후 색 차 > 30) + 구멍 메우기 + 붙은 외곽선, 남의 영역·몸 밖은 크게 바뀌고 이어진 덩어리만(긴 밑단·치마), 머리 근처의 바뀌지 않은 픽셀 제외. 머리는 턱(뒷모습은 목덜미)을 구 아랫면에 맞춰 붙이고 기본 몸의 민머리는 지운다.
- **합성**: 기본 몸 → 하의 → 상의 → 머리를 원본 해상도에서 합성한 뒤 HD(96×128)로 축소(이음매 없음). 조합 8종 × 10프레임 × 앞·뒤.

### 15.2 결과와 남은 문제
- 앞모습은 v2 완성 캐릭터와 비슷한 품질. 옷·머리를 바꿔 끼워도 체형·자세·발 위치가 같다.
- **남은 문제**: 뒷모습 앉기 기본 몸이 옆을 보고 그려짐(재생성 필요), 머리가 v2보다 약간 작음(머리 템플릿 배율 보정), 옷 가장자리 잔점 일부, 레이어를 실행 중에 겹칠지(조합 수만큼 아틀라스가 늘지 않음) 빌드 때 구울지(이음매 없음) 결정 필요.

### 15.3 게임 연결 — 실행 중 겹치기 (2026-11-23)
- **내보내기(`process.py export`)**: 파트별 HD 프레임 — 기본 몸(민머리 제거) 10프레임 × 앞·뒤, 상의·하의 레이어 10프레임 × 앞·뒤(작은 구멍 메움, 불투명 판정 70/255로 낮춰 레이어 경계 틈 방지), 머리 방향별 1장(v2 머리 크기에 맞춰 1.08배) + 프레임별 머리 중심 표(HD px). 옷 레이어 추출은 "옷 색 모델"(확실히 바뀐 픽셀로 만든 16색 팔레트에 그 자리 기본 몸 색보다 가까우면 옷)로 라벤더-회색처럼 차이가 작은 색도 잡는다.
- **아틀라스**: `part/base/<dir>/<k>`, `part/top/<id>/<dir>/<k>`, `part/bottom/<id>/<dir>/<k>`, `part/hair/<id>/<dir>`(여백 유지: 실행 중 좌우 반전). 오버라이드 `parts`에 상태별 프레임 번호·머리 위치 표·목록·이름. 서버 검증 목록 `shared/avatar-parts.json`도 함께 생성.
- **서버**: `avatar_profiles.parts`(추가 열, SQLite·PostgreSQL), 메시지 `{type:'avatar_parts', parts:{hair,top,bottom}|null}` → 검증·저장·`status` 방송. 팔레트는 유지(파트 그림이 없을 때 대체).
- **클라이언트**: 기본 몸 스프라이트가 애니메이션을 돌고, 같은 컨테이너의 하의·상의·머리 레이어가 매 프레임 그 프레임 번호와 머리 위치 표를 따라간다. 동·서는 남·북 반전. 파트를 고르지 않은 사용자는 기존 완성 캐릭터. UI: 내 상태 패널의 "옷 갈아입기"(머리·상의·하의, 기본 외형으로).
- **남은 것**: 프로필 초상화는 아직 팔레트 기준 완성 캐릭터. 파트 프레임은 게임이 지금 쓰는 4종(대기·걷기·앉기·타이핑)만 있다 — 몸짓 등은 동작 상태 머신(C4) 작업 때 파트 시트를 추가한다. 옷·머리 추가 = 옷 시트 2장(앞·뒤) 또는 머리 시트 1장(스타일 4종).
- **함께 고친 것**: p0 색 변형에서 보라 기운의 짙은 회색 바지가 상의로 잡혀 색이 바뀌던 문제(명도 하한 0.30 → 0.40).
